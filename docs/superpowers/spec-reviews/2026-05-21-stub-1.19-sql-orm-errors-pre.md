## Vocabularies (must use spec values exactly)

- **Confidence:** `low | medium | high` (no `none` in the SqlOrmErrorConfidence type — `none` means no finding emitted, not a finding state).
- **Status:** `candidate | confirmed | rejected | stale`.
- **Severity:** `info | low | medium`. **High and critical are FORBIDDEN** for this stub (spec §Severity guidance).
- **Method:** `GET | POST | HEAD | OPTIONS | OTHER`.

## Must-not assertions (negative-test grid)

Each item below MUST be exercised by a regression test:

1. No `UNION SELECT`, `OR 1=1`, `SLEEP`, `BENCHMARK`, `WAITFOR`, `LOAD_FILE`, `xp_`, `--`, `/*`, `#`, stacked statement separators in any probe payload.
2. No mutating HTTP methods (`PUT`, `PATCH`, `DELETE`); `POST` only if a prior phase already marked the request shape safe (not in this stub's MVP — skip POST entirely).
3. No confirmed finding from documentation/tutorial/blog pages that merely contain SQL-error examples.
4. No finding for text that appears only inside the scanner-supplied probe value (echo defense).
5. No SQL-injection-exploitability claim.
6. No `high` or `critical` severity emission.
7. No brute-forcing of parameter names; no wordlist fuzzing.
8. No following of URLs, file paths, or hostnames disclosed inside an error message.
9. No persistence of cookies, authorization headers, API keys, session IDs, or database passwords in the finding snippet.
10. No hostname-to-technology hard-coding.
11. No LLM/AI calls (`AI involvement: None` per spec §Safety).
12. No indefinite retry after timeouts or TLS errors.
13. No duplicate findings for the same `(target, url, method, signature_family, evidence_hash)` tuple.
14. No baseline-request skip when prior phases have NOT already stored an identical response.

## Detection coverage targets

Required signature families (one positive + one negative per family in tests):
- **mysql / mariadb** — `SQLSTATE[`, `Warning: mysql_`, `mysqli_sql_exception`, `MySqlException`, `MariaDB`, "You have an error in your SQL syntax"
- **postgresql** — `syntax error at or near`, `pg_query`, `psycopg`, `PostgreSQL`, `Npgsql`
- **sqlite** — `SQLiteException`, `sqlite3.OperationalError`
- **mssql** — `Microsoft OLE DB Provider for SQL Server`, `SQL Server Native Client`, `System.Data.SqlClient.SqlException`
- **oracle** — `ORA-` (with number), `Oracle error`
- **orm** — `SequelizeDatabaseError`, `PrismaClientKnownRequestError`, `TypeORMError`, `QueryFailedError`, `ActiveRecord::StatementInvalid`, `Doctrine\DBAL\Exception`, `Illuminate\Database\QueryException`, `HibernateException`, `JDBCException`, `MongoServerError`, `Neo.ClientError.Statement.SyntaxError`

Confidence ladder per spec §Classification:
- **high** = known SQL/ORM exception + (SQL fragment OR stack trace OR driver name OR table/column name)
- **medium** = known SQL/ORM exception alone (low context)
- **low** = weak SQL-like phrase only (`database error`) without DBMS/ORM/driver/stack/query context

## Probe rules (spec §Inputs + §Detection logic)

- `max_candidate_urls` default `40`; `max_requests_per_url` default `3`; `max_body_bytes_to_scan` default `262144`.
- `interesting_statuses` default `[400, 404, 405, 409, 422, 500, 501, 502, 503]`.
- `include_query_param_probe` default `true`; `include_path_probe` default `false`.
- Safe sentinel values: URL-encoded quote (`%27`), double-quote (`%22`), backslash (`%5C`) — no SQL operators.
- One baseline GET per candidate URL; at most one safe malformed query-param probe per URL.
