## 4. Pass/fail negative assertions

- No `useMutation` imported by slice 10 files (grep verifies).
- No editing UI (per spec "No editing needed for MVP").
- No backend mutation calls from Settings page — only `GET /api/health/`.

## 5. Acceptance criteria

- Operator can navigate to `/settings` from the sidebar.
- All 6 status fields render with current backend health.
- Polling refreshes status every 30s (inherits from the shared `useConnectionStatus` query — verified by `staleTime: 30_000` + `refetchInterval: 30_000`).
- Frontend version reads from `VITE_FRONTEND_VERSION` env var with `"dev"` fallback.

## 6. Idempotence / determinism / bounded

- Query key (`HEALTH_KEY`) is static + deterministic — React Query dedupes.
- Single endpoint, single response; no pagination concerns.
- `BoolBadge` with `ok === undefined` renders deterministic "—" sentinel.

## 7. Transport-error tolerance

- `/api/health/` 5xx or network failure → `query.isError` → error callout renders with "Backend unreachable" message.
- All status fields gracefully fall back to "—" when data is absent.
- Existing `ConnectionPill` still works (shares the same query result via shared key).
