# Stub 2.22 (tenant-org-join-abuse) — spec review

Audit of `backend/apps/stubs/tenant_org_join_abuse/` against
`docs/superpowers/specs/2026-05-18-VULN-SCANNING-COOK-BOOK/02-authentication/22-tenant-org-join-abuse.md`.

## Compliant

- **Gate discipline.** Three gates: `allow_registration_probes` RoE knob →
  `authorized_test_accounts` → `FIXTURE_TENANT_ID` env var. Each emits a typed
  `AUTH_PROBE_REFUSED` or `FIXTURE_REQUIRED` event. Covered by `test_gates.py`.
- **No mutations in passive mode.** Runner only sends the join POST when `allow_registration_probes`
  is on. Gate test covers the disabled path.
- **No AI.** Detection is deterministic marker matching only.
- **Bounded join attempts.** One join attempt per run, no loop, no guessing. Implicitly
  bounded below `max_join_attempts=3` default.
- **Transport-error isolation.** Both probes handle `submit_probe` returning `None`; runner
  emits refusal event and stops. Covered by two transport-error runner tests.
- **Confidence vocabulary.** `low | medium | high` via shared `Confidence` type alias.
- **Status vocabulary.** `candidate | confirmed | rejected` emitted by classifiers.
- **Success-marker detection.** `classify_join_success` correctly detects
  `workspace_member`, `tenant_org_join_abuse_vulnerable`, and
  `tenant_org_join_abuse_joined_existing_tenant` markers as `confirmed/high`.
- **Reject-marker detection.** `classify_join_success` guards against
  `tenant_org_join_abuse_invite_required` and `tenant_org_join_abuse_pending_approval`
  markers — false-positive gap closed and regression-tested in `test_classify.py`.
- **Separate-tenant detection.** `classify_rejected_join` returns `rejected` when
  `tenant_org_join_abuse_separate_tenant_created` is in the body.
- **Invite-required detection.** `classify_rejected_join` returns `rejected` on 401/403.
- **No hostname inference.** All detection from response body and status codes.
- **join-surface classification.** `classify_join_surface` correctly gates on path-hints
  AND body keywords. Covered by `test_classify.py`.

## Deferred (follow-up tasks)

- **Passive discovery sweep.** Spec §1 lists ~12 paths to probe with GET-only discovery
  (`/login`, `/signup`, `/register`, `/join`, `/invite`, etc.) plus HTML link/form
  inspection. MVP only probes the fixture workspace dashboard. Deferred — requires
  multi-probe loop and HTML parser.

- **Primary-account authenticated baseline (§2).** Collecting tenant display name, member
  list visibility, invite page, slug/ID via a `primary_account` login. MVP has no
  `primary_account` config field. Deferred.

- **Probe variants (§3).** Spec requires: invite URL without token, invite URL with random
  token, API join with random invite code, domain-based auto-join. MVP only runs the
  direct no-token API join. Deferred to a follow-up that extends the fixture and runner.

- **`classify_join_surface` not called from runner.** Function is implemented and tested
  in isolation but the runner removed the call (result was discarded — reviewed clean in
  code review). Surface finding emission deferred to the passive discovery sweep work above.

- **Full `TenantOrgJoinAbuseFinding` schema.** Spec defines `joined_existing_tenant`,
  `tenant_access_observed`, `synthetic_account_used`, `created_test_account`,
  `cleanup_required`, `safety_notes`, `signature`. MVP `Finding.data` stores `kind`,
  `endpoint`, `method`, `tenant_id`, `requires_manual_review`. Platform-wide field-shape
  compliance deferred (#81 analogue).

- **`max_join_attempts` config knob.** Runner makes exactly one join attempt; spec allows
  up to 3. Config field not wired. Deferred — current behaviour is safe (≤1 attempt).

- **Isolated cookie jars per account.** Spec requires separate session storage for primary
  and secondary accounts. MVP uses a single `session_headers` dict. Deferred.

- **`stale` finding path.** No code path produces `status=stale`. Platform-wide concern,
  deferred to cross-run dedup workstream.

- **Cleanup hook** (`POST /test/reset`). Spec defines a fixture cleanup route. Runner does
  not call it after each run. Deferred.
