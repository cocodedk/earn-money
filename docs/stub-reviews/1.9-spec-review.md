# Stub 1.9 (old-endpoints) — spec review

Audit of `backend/apps/stubs/old_endpoints/` against
`docs/superpowers/specs/2026-05-18-VULN-SCANNING-COOK-BOOK/01-information-gathering/09-old-endpoints.md`
(687-line enriched spec).

## Compliant

- **Read-only HTTP.** Fetcher only calls `client.get()`. No POST/PUT/PATCH/DELETE/TRACE/CONNECT. Negative-assertion §"Must not send POST..." satisfied.
- **No AI.** Detection is regex + substring + hash-equality. `AI involvement: None` per spec §Safety.
- **No credentials.** Fetcher sends no Authorization, no cookies. `allow_authenticated_requests` config field unused in MVP per spec.
- **No hostname inference.** All seeded paths static; classifier reads response evidence only.
- **Bounded request budget.** 1 baseline + 3 control + 21 seeded probes per target, transport-error-isolated.
- **Status filter.** 404 and 410 explicitly skipped at the top of `classify_probe`.
- **Same-origin discipline.** `follow_redirects=False` — runner never chases off-origin Location.
- **Confidence vocabulary.** Only `low | medium | high` emitted (MVP uses only `medium` and `high`).
- **Finding-status vocabulary.** Verdict carries `FindingStatus.CONFIRMED | FindingStatus.CANDIDATE` — typed enum, not stringly typed (post-simplify fix).
- **Header allowlist at fetch time.** `_CAPTURED_HEADERS = {deprecation, sunset, warning, link, location}`. Cookies / Authorization / arbitrary server-disclosed headers never enter the bundle. Spec §Safety "Must not persist cookies, authorization headers, tokens" satisfied at the earliest point.
- **Multi-value Link handling.** RFC 7230 §3.2.2 comma-join via `multi_items()` — a `rel="deprecation"` in any of multiple Link headers surfaces.
- **Body-marker gating on alive status.** §5 ("from each live response, extract indicators") read narrowly: body-marker check only on 200/204/206. Path-echo false positive (caught against juiceshop.cocode.dk's Express 500 page) rejected.
- **No body persistence at fetch time.** Body lives in the bundle (in-memory only) and feeds `Evidence.raw_excerpt` truncated at 200 chars — no full bodies persisted. Spec §Persistence "Store bounded snippets and hashes, not full sensitive response bodies" satisfied.
- **Per-probe transport-error isolation.** `httpx.TransportError` → `None` for that probe; loop continues. Spec §"Must not let one failing candidate abort the whole scan" satisfied.
- **Path-segment token matching.** `path.lower().split("/")` segment-membership against STALE_TOKENS. Spec §"Must not create a finding only because a word like `gold` contains `old`" satisfied via test_classify::test_random_200_without_signal.
- **5xx never creates a finding alone.** Tightened in classify after the path-echo bug surfaced. Spec §"Error statuses may be stored as Evidence but must not create a finding unless another response proves the endpoint exists" satisfied.

## Deferred (tracked tasks)

- **discovered_paths input wiring** (#87 task body). Spec §1 lists `framework_detection, server_headers, frontend_route_discovery, robots, sitemap, javascript_route_extraction, api_spec_discovery` as upstream phases. The platform has no inter-stub plumbing for this yet; MVP runs on seeded paths only.
- **Version-shadow generation** (#87 task body). Spec §1 generates `/api/v1/users` siblings when `/api/v3/users` is observed in `discovered_paths`. Blocked on `discovered_paths` wiring — defer together.
- **Cross-run idempotence + status=stale on re-run** (#82 + new #87 deferral). Spec §Persistence §"Keep historical findings and update `status` to `stale` when a previously found endpoint no longer responds as live" is a platform-wide concern (all stubs create new rows per run); requires `first_seen_at` / `last_seen_at` columns on Finding plus content-hash dedup. Tracked separately.
- **Soft-404 hash-based dedup.** Spec §3 builds a body-hash set from the 3 control probes and rejects any candidate matching it. MVP uses simpler `body == baseline_body` equality (catches SPA fallthrough on real targets — see live test on juiceshop). The richer hash-set rejection (per-namespace SPA shells, JSON 404 templates, WAF pages) is a follow-up worth landing alongside the path-echo gate eventually.
- **Redirect classification.** Spec §6 row "redirect_live" (3xx with same-origin Location) → spec §7 row 6 "weak, ambiguous, or only redirect-based" → `candidate/low`. MVP returns None for 3xx without explicit deprecation header. Needs the same-origin path helper (#86) before lifting.
- **HEAD-first request discipline.** Spec §Request discipline step 1 ("Send HEAD when head_first=true"). MVP is GET-only; saves no requests on this MVP path-list (21 entries) and matches the other Phase-1 stubs.
- **Slash / no-slash alias dedup.** Spec §8 "deduplicate by `target_id + normalized_path + endpoint_kind`" and §"both slash and no-slash variants ... keep one finding ... record both paths in `aliases`". MVP emits two findings (one per slash variant). The seeded path list intentionally carries both forms — operator's `_verified/` triage already collapses them, but the runner should ideally do it. Tracked as follow-up.
- **`aliases`, `version_family`, `version_number`, `higher_sibling_versions_seen`, `risk_summary`, `recommendation` fields on OldEndpointFinding.** MVP omits — spec §Persistence schema has 20+ fields; current Finding.data carries only the ones consumed during evidence write-back. Field shape compliance is a platform-wide ergonomics question (mirrors #81 for stub 1.8) — defer to the same workstream.

## Summary

The stub-1.9 MVP implements the spec's decision table faithfully for the seeded-paths input class and the deterministic header / body / path signal families. Spec deviations fall into two categories: (a) **platform-wide concerns** (idempotence, Finding shape, cross-run stale tracking) tracked alongside the analogous stub-1.8 deviations under #81/#82 plus new task entries on #87's body; (b) **upstream-dependent features** (discovered_paths input, version-shadow generation, redirect classification) blocked on other phases that haven't landed.

Live coverage against the three lab fixtures returned zero findings on each — the gate against Express's path-echo 500 was caught by this audit's live run and pinned in `test_classify.py::BodyMarkerTests::test_body_marker_on_5xx_ignored`.
