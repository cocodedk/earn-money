# Stub 1.10 (debug-pages) — spec review

Audit of `backend/apps/stubs/debug_pages/` against
`docs/superpowers/specs/2026-05-18-VULN-SCANNING-COOK-BOOK/01-information-gathering/10-debug-pages.md`
(614-line enriched spec).

## Compliant

### Detection logic

- **Read-only HTTP.** Fetcher only calls `client.get()`; no POST/PUT/PATCH/DELETE/OPTIONS. Forbidden-methods negative-assertion satisfied at the request boundary.
- **No method override.** `httpx.get(url)` issued without an `X-HTTP-Method-Override` header.
- **No AI involvement.** Detection is regex + substring + closed signature library. `AI involvement: None` per spec §Safety.
- **No credentials.** Fetcher sends no Authorization, no cookies, no auth refresh. `include_authenticated_paths` default-false MVP per spec.
- **Bounded request budget.** 1 baseline + 51 seeded paths = 52 GETs per target, well under spec default `max_requests=60`.
- **Status-class filter.** 404 and 410 explicitly skipped at the top of `classify_probe`.
- **Same-origin discipline.** `follow_redirects=False`; off-origin Location is never chased.
- **Body byte limit.** `FetcherConfig.max_body_bytes` default = 256000 (spec default). Body sliced at fetch time.
- **Header allowlist at fetch time.** `_CAPTURED_HEADERS_FROZEN = {content-type, location, x-debug-token, x-debug-token-link, x-runtime, x-powered-by}`. Cookies, Authorization, and arbitrary server-disclosed headers never enter the bundle.
- **Multi-value header handling.** RFC 7230 §3.2.2 comma-join via `httpx.Headers.multi_items()` so multi-Link / multi-X-Debug-Token-Link cases collapse correctly.
- **Per-probe transport-error isolation.** `httpx.TransportError` → `None` for that probe; loop continues. Spec §"Must not let one failing candidate abort the whole scan" satisfied.

### Persistence contract

- **`Evidence.source = "path"`** per shared schema.
- **Finding.confidence** from cookbook vocabulary {low, medium, high}.
- **Finding.status** typed via `FindingStatus.CONFIRMED | CANDIDATE`.
- **Finding.data.kind** uses `DebugPageKind` Literal — typo-resistant.
- **Finding.data.exposure** uses spec DebugPageExposure values: `public | blocked | login_required | redirected | unknown` (MVP emits `public` and `blocked`).
- **Finding.data.leaked_data_classes** from spec vocabulary: `stack_trace | absolute_path | environment_variable | secret_like_value`.
- **Finding.data.indicators** carry framework markers / env tokens / trace markers as flat strings.
- **Finding.data.evidence_ids** links to Evidence rows.
- **Evidence.raw_excerpt** carries a 120-byte (code-point) body snippet **after redaction**, capped at 200 chars total. Spec §Persistence "Store bounded snippets and hashes, not full sensitive response bodies" satisfied.
- **No raw bodies persisted.** Body lives in the bundle in-memory only.
- **Redaction at write boundary.** `redact_secrets` masks env-var `KEY=value`, JSON `"key":"value"`, and bare AWS access keys before the snippet is built.

## Deferred (tracked tasks)

- **HEAD-first request discipline** (spec §Request discipline step 1). MVP is GET-only — matches Phase 1 sister stubs. Not blocking for cookbook compliance.
- **`discovered_paths` input wiring.** Spec lists `framework_detection, robots, sitemap, javascript_route_extraction, api_spec_discovery` as upstream sources. Platform has no inter-stub plumbing yet; `extra_paths` argument on the fetcher is reserved. MVP runs on seeded paths only.
- **`framework_hints` input** (spec §Inputs). MVP ignores; no path-ordering optimisation yet. Defer until upstream stubs emit hints.
- **Authenticated probes** (`include_authenticated_paths` default-false). MVP unauthenticated-only.
- **Cross-run idempotence + `stale` transition** (spec §Persistence "Mark a previously confirmed finding as `stale` when the same path no longer returns matching evidence"). Platform-wide concern (mirrors stub-1.8 deferral #82); requires `first_seen_at` / `last_seen_at` columns on Finding plus content-hash dedup. Tracked under #82.
- **Redirect classification.** Spec §Redirect handling rows for `login_required` (3xx with Location to /login) and `redirected` exposure values. MVP returns None for 3xx — `follow_redirects=False` guarantees we never chase, but classifying the Location-based exposure needs the same-origin helper #86 lift first.
- **Slash / no-slash alias dedup.** Both `/server-status` and `/server-status/` emit findings — `findings/_verified` triage collapses today; runner-level dedup is a follow-up shared with stub 1.9.
- **`heapdump` truncation flag.** Spec §Persistence "mark evidence as truncated" — MVP truncates the body at `max_body_bytes` but doesn't set an explicit `truncated: bool` field on Evidence.data. Worth tracking.
- **Soft-404 hash-set dedup.** Spec §Detection logic mentions "no significant text change" but MVP uses simpler `body == baseline_body` equality (caught all SPA fallthrough cases on juiceshop). Hash-set extension shared with stub 1.9 follow-up.

## Summary

Stub 1.10 MVP implements the deterministic core of the spec's decision table for path + body + header signals. Spec deviations fall into two buckets: (a) **platform-wide concerns** (cross-run idempotence, slash-variant dedup, truncation flag on Evidence) tracked alongside the analogous stub-1.8 / 1.9 deviations; (b) **upstream-dependent features** (discovered_paths input, framework_hints, redirect classification) blocked on other phases or shared helpers (#86) that haven't landed.

Live coverage against three lab fixtures returned the expected shape on each: SPA fallthrough rejected on juiceshop, Apache mod_status correctly identified-as-blocked on dvwa, Tomcat 404s rejected on webgoat. The classifier's distinction between `public` and `blocked` exposure fires on real data without operator hand-holding.
