# Stub 1.11 (robots-txt) — spec review

Audit of `backend/apps/stubs/robots_txt/` against
`docs/superpowers/specs/2026-05-18-VULN-SCANNING-COOK-BOOK/01-information-gathering/11-robots-txt.md`
(537-line enriched spec).

## Compliant

### Detection logic

- **Single GET only.** Fetcher issues exactly one `client.get()` per
  hop; no other methods at any path. Spec §"Request rule 1: Use
  GET" + §Pass/fail negative assertion 2 satisfied.
- **No request body.** `httpx.get(url)` with no `content`/`data`
  kwarg. Spec §"Request rule 2" + negative assertion 3.
- **No credentials.** Fetcher passes no Authorization, cookies, or
  session headers. Spec §"Request rule 4" + negative assertion 4.
- **Manual same-origin redirect handling.** `httpx.Client(follow_redirects=False)`;
  the runner walks each `Location` itself, vetting origin via
  `apps.stubs._shared.url.origin`. Cross-origin Location → kind
  `cross_origin_blocked`. Spec §"Request rule 6" + negative
  assertion 7.
- **Redirect budget.** `FetcherConfig.max_redirects` default 2 per
  spec §Inputs.
- **Body byte cap.** `FetcherConfig.max_body_bytes` default 262144
  per spec §Inputs.
- **Transport-error tolerance.** `httpx.TransportError` →
  `FetchOutcome(kind="unreachable")`; classifier maps to REJECTED /
  low. Spec acceptance criteria 4.
- **Structured parsing.** `parse_robots()` honours spec §Body
  handling + §Robots groups rules: BOM strip, blank/comment skip,
  case-insensitive directives, group boundary on User-agent after
  rules, empty Disallow ignored as path hint, Sitemap as global,
  unknown directives → warnings (no crash), wildcards preserved
  raw, external URLs dropped from path hints.
- **Sensitive-path matching.** Segment + filename-component
  matching against the spec's 32-token closed list. `/products/gold`
  doesn't match `old` because gold isn't a separate component.
  `.git`/`.env` match as whole segments. Deterministic order.
- **Sitemap origin classification.** `classify_sitemap_origin` per
  RFC 6454 (scheme + host + port). Malformed URLs default to
  `cross_origin` so the runner never accidentally trusts unverified
  metadata.

### Persistence contract

- **Evidence persisted on every run**, including REJECTED/404
  outcomes. Spec §Pass/fail rule 3 (test pins this).
- **`Evidence.source = "path"`** per shared schema.
- **`Finding.confidence`** uses cookbook vocabulary {low, medium,
  high}.
- **`Finding.status`** uses `FindingStatus` enum.
- **`Finding.data`** carries the spec-prescribed shape: classification,
  http_status, redirected, indicators, *_count fields,
  same_origin_path_hints + same_origin_sitemaps + cross_origin_sitemaps
  arrays, sensitive_hints list, parse_warnings, finding_type="robots_txt".
- **`finding.data.evidence_ids`** links back to the Evidence row.
- **No raw body persisted** beyond the 200-char `raw_excerpt` —
  spec §Persistence "Store only capped body evidence".

## Deferred (tracked tasks)

- **`max_extracted_paths` / `max_extracted_sitemaps` caps.** Spec
  §Inputs lists `max_extracted_paths=200` and
  `max_extracted_sitemaps=50`. MVP serialises everything the
  parser found (in practice always far below the caps). Worth
  tightening once a corpus shows a target with > 200 disallow
  entries.
- **Per-path `RobotsTxtSignature` rows.** Spec §Persistence
  defines a `RobotsTxtSignature` type with one row per
  disallow/allow/sitemap entry. MVP rolls everything into
  `Finding.data` lists/counts — adequate for the read API but
  doesn't let the operator query "which targets have a sensitive
  path hint of `.env`?" without scanning Finding.data JSON. Lift
  alongside platform-wide #82 (cross-run idempotence) since both
  changes touch the persistence model.
- **Cross-run idempotence + `stale` transition.** Platform-wide
  concern (mirrors stubs 1.8/1.9/1.10), tracked under #82.
- **Refactor stub 1.6 hidden_routes/extractors/robots_txt.py to
  use `parse_robots()`** — tracked under #105. Stub 1.6 currently
  has a simpler Disallow-only extractor that doesn't filter
  external URLs.
- **Shared body-marker AND/OR helpers + shared Literal types** —
  tracked under #94 and #95.
- **Custom `debug-pages-lab`-style fixtures** for robots edge
  cases (redirect chains, large bodies, malformed). MVP tests
  the edge cases via mocked_fetcher; standing up dedicated
  HTTP test servers per spec §Test fixtures table is deferred.
- **Body streaming.** `response.text` reads the full body before
  truncation. Tracked under #64 (was scoped for stub 1.3, expands
  to cover all stubs).

## Summary

Stub 1.11 MVP implements the spec's deterministic core: GET-only,
manual same-origin redirect handling, structured robots.txt
parsing, sensitive-path matching by segment + filename component,
and a 10-row response-classification decision table. Spec
deviations fall into two buckets: (a) platform-wide concerns
(cross-run idempotence, per-row signature persistence, body
streaming) tracked alongside the analogous stub-1.8/1.9/1.10
deviations; (b) cross-stub lifts (parse_robots() rollout to stub
1.6, shared types and body-match helpers) tracked under #105 /
#94 / #95.

Live coverage against three lab fixtures returned the expected
classification on each: `present` on Juice Shop and DVWA,
`not_found` on WebGoat. Classifier vocabulary matches reality
without operator hand-holding.

Two follow-up tasks were filed during slice work:
- **#94** — shared body-match helpers (`_shared/body_match.py`).
- **#95** — shared cookbook Literal types (`_shared/types.py`).
- **#105** — stub 1.6 → `parse_robots()` rollout.
