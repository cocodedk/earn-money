# Stub 1.12 (sitemap-xml) — spec review

Audit of `backend/apps/stubs/sitemap_xml/` against
`docs/superpowers/specs/2026-05-18-VULN-SCANNING-COOK-BOOK/01-information-gathering/12-sitemap-xml.md`
(645-line enriched spec).

## Compliant

### Detection logic

- **Read-only HTTP.** Fetcher only calls `client.get()`. No POST/PUT/PATCH/DELETE/OPTIONS/TRACE/CONNECT.
- **No request body.** `httpx.get(url)` without data/content kwarg.
- **No credentials.** Fetcher sends no Authorization, cookies, or session headers.
- **Body byte cap.** `FetcherConfig.max_body_bytes` default 2_000_000 per spec §Inputs; cap → `kind="too_large"` with bounded sample surfaced.
- **Tolerant XML parser.** Regex-based; spec §Acceptance criteria "handles malformed XML without crashing" satisfied. Sees unclosed tags / missing locs / orphan url blocks without aborting.
- **Robots-style fragment + dedup.** `urldefrag` strips fragments; entries deduplicated by normalized loc per spec §Persistence dedup rule.
- **Sitemap kind detection.** `<urlset>` vs `<sitemapindex>` distinguished at parser entry; unknown kind for HTML / empty / unidentified content.
- **URL scope classification.** RFC 6454 origin compare via shared `_shared/url.origin`; relative paths in_scope by definition; unparseable locs → `unknown`.
- **Deterministic URL tagging.** 10-tag pattern table per spec §Deterministic indicators (admin_hint, api_hint, auth_hint, backup_hint, debug_hint, docs_hint, legacy_hint, test_hint, staging_hint, upload_hint, parameterized_url).
- **Per-probe transport-error tolerance.** `httpx.TransportError` → `kind="unreachable"`; runner records the finding without crashing the scan.
- **Body cap defence-in-depth on the parser.** Parser-side `_MAX_BODY_BYTES = 1MiB` cap protects against fetcher contract relaxation.

### Persistence contract

- **Evidence.source = "path"** per shared schema.
- **Finding.confidence** uses cookbook vocabulary {low, medium, high} via the shared `Confidence` Literal.
- **Finding.status** uses `FindingStatus` enum.
- **Finding.data** carries the spec-prescribed shape: classification, http_status, sitemap_url, indicators, extracted_url_count, in_scope_url_count, out_of_scope_url_count, tag_counts, sample_urls, evidence_ids, finding_type="sitemap_xml".
- **sample_urls capped at 10** entries to keep the row size bounded.
- **Evidence linked via `finding.data.evidence_ids`.**

### Live-fixture validation (2026-05-19)

- **juiceshop.cocode.dk** — `sitemap_parse_error` / 200. `/sitemap.xml` returns SPA HTML (not a real sitemap). The parser correctly classifies the body as "unknown" kind and the classifier emits the parse_error candidate per spec — the spec-compliant outcome for an HTML false positive.
- **dvwa.cocode.dk** — `not_found` / 404 (no sitemap published).
- **webgoat.cocode.dk** — `not_found` / 404 (no sitemap published).

The HTML-false-positive case fires on real data and is correctly rejected by the parser's kind detection.

## Deferred (tracked tasks)

- **Nested sitemap fetching.** Spec §Sitemap index handling: fetch child sitemaps up to `max_fetch_depth` and `max_nested_sitemaps`. MVP detects the index and reports child URLs as `extracted_url_count` but doesn't fetch them. Track on this task.
- **Per-URL `SitemapXmlSignature` rows.** Spec §Persistence defines one signature per extracted URL with parent_signature_id linking. MVP rolls everything into Finding.data lists/counts.
- **Plain text + gzipped sitemap formats.** Spec §Body parses lists `text_url_list` and `gzip_xml` parsers. MVP is XML only.
- **`max_sitemap_urls=10_000` cap.** Parser dedup keeps the entry list bounded organically but doesn't truncate at exactly 10K.
- **Robots-driven sitemap seeds.** Spec §Inputs lists "robots.txt evidence" as an optional input — the runner could read robots.txt's `Sitemap:` directives and use them as additional seeds. Cross-stub plumbing not landed yet.
- **Cross-run idempotence + `stale` transition** — platform-wide concern tracked under #82.
- **#109 stub 1.6 sitemap_xml extractor → parse_sitemap_xml()** rollout (mirror of #105).
- **Body streaming on the fetcher** — tracked under #64 (scope expanded to cover all four fetchers).
- **Spec §Test fixtures** lists `sitemap-index`, `sitemap-malformed`, `sitemap-html-false-positive`, `sitemap-oversized` fixture variants. MVP tests the edge cases via mocked_fetcher; standing up dedicated HTTP test servers is deferred (live coverage on juiceshop/dvwa/webgoat is adequate smoke for now).

## Summary

Stub 1.12 MVP implements the deterministic core of the spec's
decision table for XML sitemaps. Spec deviations cluster around
optional/upstream features (nested sitemap fetching, plain-text +
gzip parsers, robots.txt-driven seeds, per-URL signature rows)
that are tracked or noted for the next implementation pass.

Live coverage against three lab fixtures returned the expected
shape on each: parse_error on Juice Shop's HTML masquerading as
a sitemap, not_found on DVWA + WebGoat. The HTML-false-positive
rejection fires on real data without operator hand-holding.

- **#64** scope expanded to cover stubs 1.10 + 1.11 + 1.12 fetcher body streaming.
- **#109** stub 1.6 sitemap_xml extractor → parse_sitemap_xml() rollout (mirror of #105).
