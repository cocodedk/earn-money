## Coordinator's notes for the consumer pipeline

**1. Universal vuln classes across the three programs** (high-priority detection targets):
- **IDOR** (bykea 2, algolia 1 historical, h1-sec 2) — every program has at least one. Cross-cutting Phase 6 priority for `clawpwn`.
- **Info-Disclosure** (bykea 2, algolia 2, h1-sec 4) — every program has multiple. The most universal class in the corpus.
- **Auth-Bypass / broken access control on object IDs** (bykea 1, algolia 1, h1-sec 1) — every program has at least one. Same architectural shape as IDOR but separately classified.

**2. Vuln classes EMPTY across all three programs in-window** (non-priority for Phase 6 against this benchmark set, though other corpora may still justify them):
- SQLi
- XXE
- Path-Traversal
- Subdomain-Takeover
- Crypto
- Race-Condition

**This is a meaningful signal.** `clawpwn` has invested significantly in SQLi (sqlmap), XSS, path-traversal (portswigger_path_traversal), CSRF plugins — but for the three BBPs currently onboarded into earn-money, **those classes have zero recent disclosures**. The highest-leverage Phase 6 plugin work for earn-money's revenue path is IDOR / Info-Disclosure / Auth-Bypass detection, NOT the canonical OWASP top-10 split clawpwn has been targeting.

**3. Auth picture across the corpus:**
- ~85% of in-window disclosures require authentication (rider/driver/dashboard tokens).
- Implication: an unauthenticated subfinder+httpx+nuclei sweep will mostly miss the high-value bugs. Investment in **authenticated scanning** (token-aware probe flows, post-login surface enumeration) is the multiplier here.

**4. Detection difficulty distribution:**
- `regex-friendly`: 3 entries (PHP-FPM status page, web-cache-deception, `/reports/:id.json` disclosure). Easy wins; clawpwn likely already catches the first two patterns.
- `requires-auth`: 7 entries. Needs authenticated scanning.
- `requires-business-logic`: 5 entries. Trip lifecycle, feedback workflows, duplicate-report workflows — needs flow-context awareness.
- `requires-payload-crafting`: 2 entries (both SSRF in PDF generator). Needs vector-specific knowledge.
- `requires-chain` / `unclear`: 3 entries.

**5. Caveats:**
- Disclosed-date precision is approximate (±6 months) — derived from H1 report-ID ranges rather than per-report timestamps (H1 pages are JS-rendered and didn't expose dates via plain WebFetch).
- The Algolia in-window corpus came back EMPTY under multiple search strategies. If Algolia-specific signal is needed, consider broadening to indexed write-ups of Algolia API-key leakage (CloudSEK, YesWeHack, ProjectDiscovery research) rather than HackerOne disclosures.
- This corpus refreshes when new programs are onboarded; `agent-coordinator` will deliver updated JSONs on demand.

## Schema

Each per-program JSON has shape:

```json
{
  "program": "hackerone/<slug>",
  "source": "<derivation sources>",
  "generated_at": "<UTC ISO timestamp>",
  "in_window_range": "<from-date> to <to-date>",
  "disclosures": [
    {
      "report_url": "https://hackerone.com/reports/<id>",
      "title": "...",
      "severity": "critical | high | medium | low | informational",
      "disclosed_date": "YYYY-MM | YYYY",
      "bounty_usd": <int|null>,
      "asset_pattern": "...",
      "vuln_class": "<canonical-tag>",
      "vector_summary": "<1-2 sentences>",
      "auto_detectable_hint": "regex-friendly | requires-auth | requires-business-logic | requires-chain | requires-payload-crafting | requires-fuzzing | unclear"
    }
  ],
  "summary": { /* per-program aggregate stats */ }
}
```

`vuln_class` canonical values: SQLi, XSS, IDOR, SSRF, RCE, Auth-Bypass, Path-Traversal, XXE, CSRF, Open-Redirect, Info-Disclosure, Crypto, Race-Condition, Logic-Flaw, Subdomain-Takeover, Misc.
